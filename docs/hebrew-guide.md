# מדריך עברי לפרויקט הטבלה

## מה נבנה כאן

הפרויקט מציג טבלת React גנרית ב-JavaScript בלבד, בלי TypeScript, שמקבלת שני דברים:

- `columns`: הגדרת העמודות, הסדר שלהן, השם שלהן, הטיפוס שלהן והרוחב.
- `initialData`: מערך שורות, כאשר כל שורה מכילה `id` ואת הערכים לפי מזהי העמודות.

הטבלה לא מכירה את עולם ה-"employees". זה בכוונה. היא יכולה לעבוד עם דאטה אחר כל עוד הוא מגיע באותה צורה.

## נקודות חשובות לראיון

אפשר להסביר שבחרנו לחלק את הקוד כך:

- קומפוננטות React אחראיות על תצוגה ואינטראקציה.
- hooks אחראים על state מורכב.
- utilities הם פונקציות טהורות שאפשר לבדוק בלי React.

זו חלוקה טובה כי היא עושה את הקוד קל יותר להבנה, בדיקה ושימוש חוזר.

חשוב: המבנה לא אמור להיראות כמו מערכת ענקית. הוא מחולק לכמה קבצים קטנים כדי שיהיה קל להסביר אותו, אבל עדיין נשאר בגודל הגיוני לפרויקט של שלושה ימים.

## איך העריכה עובדת

כאשר עורכים תא, הערך החדש לא נשמר מיד לתוך השורות המקוריות. הוא נשמר קודם בתוך `draftChanges`.

זה מאפשר שני דברים:

- `Save changes`: מאחד את כל השינויים לתוך הדאטה המקומי.
- `Cancel`: מוחק את כל השינויים שלא נשמרו.

זה גם מראה הבנה טובה ב-state management: יש הפרדה בין מידע שמור לבין מידע זמני.

## איך הוירטואליזציה עובדת

במקום לרנדר את כל 2,500 השורות למסך, הטבלה מחשבת אילו שורות אמורות להיות גלויות לפי:

- גובה שורה קבוע.
- גובה אזור הגלילה.
- מיקום הגלילה הנוכחי.
- `overscan`, כלומר עוד כמה שורות לפני ואחרי בשביל גלילה חלקה.

הפונקציה המרכזית היא `getVirtualRange`. היא נמצאת ב-`src/utils/virtualRows.js`, והיא נבדקת בבדיקות יחידה.

## למה אין ספריית טבלה

בדרישות כתוב שאפשר להשתמש בספריות לכל דבר חוץ מהטבלה עצמה. לכן הטבלה נכתבה ידנית, כולל:

- הצגת עמודות.
- הסתרה והצגה של עמודות.
- עריכת תאים.
- שמירה וביטול מקומיים.
- וירטואליזציה פשוטה.

זו נקודה טובה להגיד בראיון כי היא מראה שעמדת בדרישה המרכזית.

## איך להריץ

בסביבה עם `npm`:

```bash
npm install
npm run dev
```

בדיקות:

```bash
npm test
```

אם אין `npm`, צריך להתקין Node.js רגיל שכולל npm, ואז להריץ את הפקודות.

## איך להסביר את ה-schema

העמודות המקוריות מהדרישה כוללות:

- `id`
- `ordinalNo`
- `title`
- `type`
- `width`

הוספנו רק שני דברים:

- `options`: בשביל עמודות מסוג בחירה, כדי לדעת מה האפשרויות ב-`select`.
- `format`: בשביל עיצוב מספרים, למשל כסף.

לא שינינו שדות קיימים ולא הסרנו כלום, וזה בדיוק לפי ההנחיה במסמך.
